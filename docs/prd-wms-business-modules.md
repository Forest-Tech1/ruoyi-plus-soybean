# 一、基础数据 — 平台仓库管理

**菜单路径**：基础数据 → 平台仓库管理

### 1. 页面概述

维护「业务平台」及其下属的「实体仓库」档案。典型场景：新接入平台、录入海外仓地址、按国家筛选仓库、批量启停仓库、从 Excel 批量导入仓库。

### 2. 页面布局

| 区域 | 内容 |
|------|------|
| 顶部标题栏 | 页面标题「平台仓库管理」；右侧「新增平台」（有权限时）。 |
| 左侧 | 「平台列表」：搜索框 + 可滚动的平台卡片（名称、代码、启用状态、仓库数量角标）；每条有「更多」菜单。 |
| 右侧主体 | 仓库检索条件 + 勾选后的批量操作条 + 仓库数据表格 + 底部分页。 |

弹窗/抽屉：新增/编辑平台、新增/编辑仓库、仓库详情、导入仓库。

### 3. 功能说明

| 名称 | 作用 | 触发条件 | 结果反馈 |
|------|------|----------|----------|
| 新增平台 | 打开平台表单 | 有新增平台权限 | 保存成功提示，左侧列表刷新 |
| 平台列表搜索框 | 按平台名称或代码过滤列表 | 始终 | 列表即时变化 |
| 平台卡片 | 选中平台，右侧展示该平台下仓库 | 始终 | 右侧表格切换 |
| 平台「更多」 | 编辑；启用/停用 | 有对应权限 | 停用且仍有启用仓库时二次确认；成功有提示 |
| 仓库关键字 | 按仓库代码/名称筛选 | 始终 | 刷新列表 |
| 状态 | 筛选启用/停用 | 可清空为全部 | 刷新列表 |
| 国家/地区 | 多选筛选 | 可清空 | 刷新列表 |
| 导入仓库 | 打开 Excel 导入向导 | 有导入权限且存在平台 | 见导入流程 |
| 导出 | 导出当前筛选结果（Excel） | 有导出权限且已选中平台 | 浏览器下载 |
| 新增仓库 | 打开表单，默认当前选中平台 | 有新增权限且存在平台 | 保存后刷新 |
| 批量启用 / 批量停用 | 勾选的多条批量改状态 | 有状态权限且至少一行 | 成功提示并清空勾选 |
| 仓库代码（可点） | 复制代码 | 始终 | 成功或失败气泡 |
| 仓库名称（可点） | 打开仓库详情 | 始终 | 抽屉展示详情与操作记录 |
| 编辑 | 编辑仓库 | 有编辑权限 | 保存后刷新 |
| 停用 / 启用（行） | 单条改状态 | 有状态权限 | 二次确认后刷新 |

### 4. 操作流程

**新建平台与仓库**：进入页面 → 新增平台并保存 → 左侧选中该平台 → 新增仓库填写保存。

**批量导入**：选中平台 → 导入仓库 → 上传 Excel → 解析并预览 → 核对后确认导入。【部分行有误时】以系统提示及后端策略为准。

**异常**：网络失败一般有错误提示；文件格式不对时预览可能为空或提示检查表头。

### 5. 数据展示说明（仓库列表主要列）

| 列名 | 含义 | 数据来源 |
|------|------|----------|
| 仓库代码 | 仓库唯一编码 | 新建/导入/后台 |
| 仓库名称 | 展示名称 | 同上 |
| 国家/地区 | 国旗与国家名（已知代码时） | 档案 |
| 详细地址 | 街道、城市、州省等组合展示 | 档案 |
| 邮编 | 邮政编码 | 档案 |
| 单托CBM | 每托盘立方米，未填显示「—」 | 档案 |
| 状态 | 启用 / 停用 | 变更结果 |
| 创建时间 | 建档时间 | 系统 |

导入 Excel 列说明见界面「Excel 列与系统字段」提示。

> 📌 **后端补充**
>
> **1. 数据从哪里来**
>
> - **平台名称、平台代码**：由用户在「新增/编辑平台」中填写；**平台代码在全系统内唯一**，保存后**不允许修改**。
> - **仓库名称**：新建时若未单独填写展示名称，系统会用**规范化后的仓库代码**作为默认展示名称；后续可在编辑时修改。
> - **仓库代码、国家/地区、地址、邮编、城市、州省、单托立方米、备注、状态**：来自用户手工维护或 Excel 导入；**单托立方米**未填写时，新建会落为系统默认立方米/托（与仓储预分配兜底口径一致，一般约 1.8）。
> - **创建时间**：在每条仓库档案**首次保存成功**时由系统自动生成，后续不变。
> - **左侧平台卡片上的仓库数量**：按当前租户下该平台关联的仓库条数实时统计。
> - **详情抽屉中的操作记录**：在名称、地址、状态、单托立方米等字段发生变更时追加一条文字说明（含变更前后摘要）。
>
> **2. 提交后发生了什么**
>
> - **保存平台**：校验平台代码唯一性；通过后写入档案。
> - **保存仓库**：校验所属平台处于可维护状态（已停用的平台不能再增改其仓库）；新建时校验仓库代码全局唯一；通过后写入并记一条「新增仓库」日志。
> - **启用平台**：更新平台状态；同时将该平台下属原本为停用状态的仓库**批量改回启用**（用于恢复业务）。
> - **停用平台**：可将下属仍为启用状态的仓库**批量改为停用**（与启用不是对称反操作；启用平台不会自动批量启用下属仓库）。
> - **停用前校验接口**：系统在用户确认前可返回「仍有 N 个启用仓库」的数量，供界面二次确认（避免误停）。
> - **Excel 导入确认**：系统**跳过预览阶段标红的错误行**，只对无错误的行执行新增或更新；导入结束刷新列表。
>
> **3. 校验规则（失败时提示示例）**
>
> - **平台**：平台代码必填且唯一；重复时提示「平台代码已存在」；平台不存在时提示「平台不存在」。
> - **仓库**：所属平台必须存在且未停用；仓库代码必填、**全局唯一**、长度与字符集符合模板要求（常见为 1～20 位字母、数字或连字符）；国家/地区为**两位字母**；详细地址必填且不超过规定长度；单托立方米须大于 0 或留空；**不允许修改仓库代码**、不允许通过编辑把仓库换到另一个平台。
> - **Excel 行级**：平台代码须对应已启用平台；仓库代码不能与文件内其他行重复；勾选「允许更新已存在」时，已存在的仓库必须与 Excel 中的平台一致，否则提示跨平台冲突；各类「不能为空」「超长」「格式不符」均有对应中文说明（见预览列）。
>
> **4. 状态变化说明**
>
> - 仓库 **启用 ↔ 停用** 即用户所选状态；批量与单行一致。
> - 平台 **停用** 可导致下属启用仓库被批量停用；平台 **启用** 不自动恢复下属仓库（需用户在仓库列表单独启用）。
>
> **5. 关联影响**
>
> - 平台仓库档案中的 **单托立方米** 会被仓储侧按「平台 + 仓库」解析，用于体积换算板数等（与上架、预分配相关页面口径一致）。
> - **仓库代码**在拆柜入库、派送解析、开放平台接口等多处用于匹配「目的地/海外仓」，修改受限是为避免历史单据对不上。
>
> **6. 异常处理说明**
>
> - **网络超时 / 网关错误**：与其它模块一致，前端展示接口返回的失败文案或通用错误提示。
> - **导入解析失败**：提示「解析 Excel 失败」并附带简要原因。
> - **导入确认为空**：提示「导入数据为空」。
> - **并发或重复提交**：关键写操作可能带防重复提交保护，极端重复会返回业务失败提示。

## 2.1 拆柜订单

**菜单**：订单管理 → 拆柜订单（若存在隐藏的旧路由，以菜单为准）

### 1. 页面概述

管理海运柜到仓后的拆柜业务单：筛选与查看、导入派送类 Excel、手工新建、调整排期与标签、拆柜完成/异常、导出拆柜单与卡板贴。

### 2. 页面布局

| 区域 | 内容 |
|------|------|
| 折叠搜索区 | 「搜索」；右侧「导入订单」「新建单」；展开为时间范围与筛选 + 重置/搜索 |
| 列表区 | 标题「拆柜订单」；刷新与列设置；**状态筛选标签**（全部、待安排、待拆柜、拆柜完成、异常）；数据表 |

弹窗/抽屉：导入预览、新建/编辑单、详情（基础资料 + 入库计划）、备注、预库位地图选择等。

### 3. 功能说明（摘要）

**搜索区**

| 名称 | 作用 | 触发条件 | 结果反馈 |
|------|------|----------|----------|
| 下单时间 | 筛选下单时段（默认约前后一月，可改） | 始终 | 刷新列表 |
| 拆柜完成时间 | 时间范围筛选 | 可选 | 刷新列表 |
| 预计拆柜时间 | 日期范围筛选 | 可选 | 刷新列表 |
| 拆柜轮次 / 订单等级 | 字典下拉 | 可选 | 刷新列表 |
| 柜号 / 提单号 | 关键字 | 可选 | 刷新列表 |
| 导入订单 | 多文件解析预览后导入 | 有导入权限 | 成功刷新列表 |
| 新建单 | 维护主单与入库计划 | 有新建权限 | 保存后刷新 |
| 重置 / 搜索 | 清空或查询 | 始终 | 刷新列表 |

**状态标签**：点击切换列表状态筛选。

**表格**

| 名称 | 作用 | 触发条件 |
|------|------|----------|
| 柜号 | 单击复制；双击详情 | 始终 |
| 拆柜轮次、预计拆柜时间、订单等级、拆柜口、标签 | 双击行内编辑 | 待安排/待拆柜且有编辑权限 |
| 标签 HOLD | 业务暂扣标识，不可随意删除 | 数据决定 |
| 更多 | 详情、备注、取消完成、标记/取消异常、导出拆柜单、卡板贴 Word/ZIP、完成拆柜、删除等 | 权限 + 当前状态 |

### 4. 操作流程

**导入**：导入订单 → 选文件 → 解析并预览 → 右侧选柜号核对 → 确认导入。

**完成拆柜**：更多 → 完成拆柜 → 确认。

**异常**：接口失败提示错误；校验失败时表单或导入预览提示。

### 5. 数据展示说明（列表主要列）

柜号、下单日期、提单号、拆柜轮次、状态、拆柜完成时间、预计拆柜时间、入库仓库、订单等级、拆柜口、标签、货物数量、货物重量、备注等。

详情抽屉含入库计划与系统预库位；预计打板数与体积关系见界面说明。

> 📌 **后端补充**
>
> **1. 数据从哪里来**
>
> - **柜号、提单号、下单日期、拆柜轮次、订单等级、拆柜口、标签、货物件数与重量、备注**：来自用户新建/编辑，或派送类 Excel 导入汇总；派送导入会把多行货品归并到**同一柜号主单**，并汇总件数与重量。
> - **入库仓库**：保存时优先使用**当前登录租户在企业档案中的企业名称**作为主单上的「入库仓库」展示值；若未配置则退回界面传入值。
> - **拆柜完成时间**：用户在流程中标记「完成拆柜」时可由系统写入当前时间（若此前为空）；「取消完成」会清空该时间并按规则重算订单状态。
> - **预计拆柜日期**：仅存**日期当天**（不含时分秒）；用户清空后会影响下方「状态自动规则」。
> - **状态（待安排 / 待拆柜 / 拆柜完成 / 异常）**：主要由系统按规则维护（见下文）；已完成与异常不会因编辑预计日期被覆盖。
> - **入库计划明细**（订单号、货件编码、体积重量等）：手工或导入写入；导入时每一行至少应能解析出「系统订单号」与「货件编码」中的一项（具体以导入模板与解析规则为准）。
>
> **2. 提交后发生了什么**
>
> - **新建/编辑保存**：在未处于「拆柜完成」「异常」的前提下，系统根据**是否填写预计拆柜日**自动把主单状态置为 **【待拆柜】**（有日期）或 **【待安排】**（无日期）；随后保存入库计划行。
> - **完成拆柜**：将状态置为 **【拆柜完成】**；若尚未记录拆柜完成时间，则记录为当前时间。
> - **取消完成**：仅当当前为 **【拆柜完成】** 允许；清空拆柜完成时间后，系统按「预计拆柜日有无」回到 **【待拆柜】** 或 **【待安排】**。
> - **标记异常**：状态变为 **【异常】**（若已是异常则幂等成功）。
> - **取消异常**：若此前已有拆柜完成时间，则回到 **【拆柜完成】**；否则按预计拆柜日回到 **【待拆柜】** 或 **【待安排】**。
> - **删除订单**：删除主单及其入库计划，并清理与库位预排相关的映射（会影响库存列表、库存数据、平面图占用等下游展示）。
> - **派送类导入确认**：同一文件只允许**一个柜号**；多单柜需拆分文件；系统生成主单默认下单日期为**当天**，提单可为空串；入库计划按行生成。
> - **标准 Excel 行导入**：以「柜号 + 提单号 + 拆柜轮次」识别是否同一单；重复时可要求勾选「更新已存在」。
>
> **3. 校验规则（失败时提示示例）**
>
> - **新建主单**：入库计划至少 **1 条**，否则提示「入库计划至少填写1条」。
> - **导入（标准）**：柜号、下单日期必填；重复且未勾选更新 → 「柜号、提单号与拆柜轮次已存在相同订单…」。
> - **派送文件**：不得出现多种柜号；不得存在柜号为空的行；每行须能解析出订单号或货件编码至少一项。
> - **取消完成 / 取消异常**：状态不符合前置条件时分别提示「仅已完成的订单允许取消完成」「仅异常状态允许取消异常」。
>
> **4. 状态变化说明（核心规则）**
>
> - 对**非**「拆柜完成」「异常」的单据：**有预计拆柜日 → 【待拆柜】**；**无预计拆柜日 → 【待安排】**（保存或编辑后会按此刷新，覆盖此前在待安排/待拆柜之间的旧值）。
> - **【拆柜完成】** 与 **【异常】** 不受上述「预计拆柜日」规则自动改写（除非执行「取消完成」「取消异常」）。
>
> **5. 关联影响**
>
> - 入库计划参与 **预排库位 / 上架规则 / 库存数据与平面图占用**；删除或重算会影响这些页面的数量与展示。
> - **标签 HOLD**：若任一入库计划行带业务暂扣含义的标记，列表可出现「存在 HOLD」类提示（由入库计划聚合得出）。
>
> **6. 异常处理说明**
>
> - **导入解析失败**：提示「解析文件失败」并附文件名与原因摘要。
> - **订单不存在**：提示「订单不存在或已删除」。
> - **网络类错误**：与其它接口一致，展示后端返回文案或通用失败提示。

## 2.2 库存列表

**菜单**：订单管理 → 库存列表

### 1. 页面概述

查看导入等产生的预排库位结果列表。

### 2. 页面布局

标题与工具栏；搜索行（柜号、提单号、仓库代码）；表格；分页。

### 3. 功能说明

| 名称 | 作用 | 触发条件 | 结果反馈 |
|------|------|----------|----------|
| 柜号 / 提单号 / 仓库代码 | 查询条件 | 始终 | 搜索刷新 |
| 搜索 / 重置 | 查询或清空 | 始终 | 刷新列表 |

> - **规则内容**：用户在「新建/编辑规则」中配置的库区、库位、库区类型、存放方式、派送方式、平台等条件组合，以及条件内部的 **优先级数字**（数字越小通常越先尝试，具体以保存时的规则版本为准）。
> - **兜底库区与兜底库位**：在「分配兜底」中单独保存；须至少选择兜底库区；可选限定具体库位且须归属所选库区。
>
> **2. 提交后发生了什么**
>
> - **保存规则 / 保存兜底**：写入配置表；之后的 **预库位试算** 将按最新配置执行。
> - **预分配引擎（面向产品描述）**：对每条入库计划，系统按规则集逐条匹配；同一规则内多条件按维护时的优先级排序；若所有规则都无法给出可用分配，则尝试 **兜底库区中的可用库位**（容量、混放限制仍生效）；仍失败则可能不产生映射或产生拆分结果，详见异常日志。
>
> **3. 校验规则**
>
> - 兜底保存时：**兜底库区必选**；若选了库位主键，必须真实存在且属于所选库区。
>
> **4. 关联影响**
>
> - 直接影响 **拆柜入库计划上的系统预库位**、**库存列表/库存数据/平面图占用**。
> - 库区页历史上单独的「上架条件」入口若仍存在，应与本书签 **上架配置** 保持一致，避免两套说法。
